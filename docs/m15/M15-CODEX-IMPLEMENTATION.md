## 1. 质量问题：先审计、再统一，而不是主观大改

以下是远程 M13 源码可核实的技术背景：

- `frontend/src/stores/theme.ts` 使用 `travel-notes.theme`，仅 `system` / `light` / `dark` 三态。
- `frontend/public/theme.js` 在应用挂载前同步设置明暗主题，已经具有防闪烁基础。
- `frontend/src/styles/main.css` 定义 `--color-pine`、`--color-pine-deep`、`--color-pine-soft`、`--color-cream`、`--color-surface` 等语义不够明确的历史调色 Token；各页面大量引用旧命名。
- `frontend/src/components/SiteHeader.vue` 的设置浮层仅提供三态选择。
- 页面也有各自 scoped CSS，创作者页、详情页、Vditor、后台及灯箱采用了部分独立的尺寸、圆角、背景和弹层风格。用户反馈存在割裂感；**具体表现须以同分辨率真实浏览器截图审计，不能把假设写成已复现问题**。

第一步建立设计审计矩阵。依次检查：发现页/瀑布流、攻略详情与评论抽屉、作者主页、写攻略(Vditor)、目的地列表与详情、AI 行程、收藏/行程、登录/注册、个人设置、管理员后台/AI 设置、图片灯箱；每页在桌面 1440、平板 768、手机 390 的浅/深主题下截图，指出具体不一致：字体/字号层级、间距、宽度、边框、圆角、投影、背景层级、表单/按钮、图标、弹层、动效、空状态与错误状态。

审计完成后把问题分为 P0：明显错位/不可读/主题不一致/溢出；P1：视觉重复与质感问题；P2：微调。优先修共性设计系统，禁止只在单页零散打补丁。

## 2. 建立统一的主题与设计 Token 系统

按真正的设计系统组织颜色与空间，而不依赖到处手写的深绿数值：

- 基础层：`--ui-bg-page`、`--ui-bg-surface`、`--ui-bg-elevated`、`--ui-text-primary`、`--ui-text-secondary`、`--ui-border-subtle`、`--ui-shadow-*`、`--ui-radius-*`、`--ui-space-*`、`--ui-motion-*`。
- 主题层：`--ui-accent`、`--ui-accent-hover`、`--ui-accent-pressed`、`--ui-accent-soft`、`--ui-accent-on`、`--ui-focus-ring`、`--ui-link`、`--ui-selection`。浅色和深色独立推导，确保可读性。
- 业务语义：成功/警告/错误/危险/管理员审核状态保留独立语义颜色，不能因用户选择粉色而把错误消息也染成粉色。
- 与 Tailwind CSS v4 `@theme` 和当前 `bg-pine` / `text-pine` 等类兼容。可先建立旧 Token 到新 Token 的别名桥接、逐步迁移组件，不允许一次性全局替换后导致旧组件失色。
- 图像、摄影、作者头像和内容封面保持原样；品牌识别可保留原 Logo 造型，但周边强调色要一致。图片预览应继续使用专业的深色中性遮罩，工具栏可适度吸收主题强调色，不应把照片背景染色。
- 统一标题层级、字体组合（保留山水间现有衬线标题风格，正文以可读性为先）、布局宽度、卡片边框和阴影、按钮尺寸、表单高度、浮层和抽屉层级、圆角、动效曲线。兼顾浏览器缩放和小屏。

## 3. 自定义主题色调：用户功能（P0）

### 3.1 外观与配色分离

现有的 `跟随系统 / 浅色 / 深色` 继续独立存在。新增“主题色调”设置：

- 默认“山水绿”。内置建议预设：山水绿 `#187650`、海岸蓝 `#3578C8`、暮霞紫 `#8064C8`、落日橙 `#C87842`、樱花粉 `#C7658B`、石墨灰 `#667487`。这些 HEX 是**种子色**，不应直接作为所有文本/按钮背景色；最终由设计系统派生满足对比度的色阶。
- 增加“自定义颜色”：通过原生 `input[type=color]` 或经过验证的同类组件选择 HEX；可输入 HEX 值，非法值拒绝并显示错误，不拼接任意 CSS。
- 可以有“柔和/标准/鲜明”色调强度（P1），影响背景氛围、弱强调面和交互强度，不影响可读性及告警语义。不要为了实现这个选项牺牲 P0 的基础稳定性。
- 预设色卡提供名称、颜色圆点、选中标识和键盘可访问状态；自定义选择时实时在一个小型预览区显示按钮、标签、背景和正文链接样式。变化即时全站生效，无需点击保存。
- 有“恢复山水绿默认配色”；恢复只重置配色，**不应擅自改变浅色/深色/系统设置**。
- 无登录也可以使用。第一期仅保存在当前浏览器（localStorage），不新增数据库和服务端账号同步；以后如用户另行要求再考虑跨设备同步。

### 3.2 可靠的持久化与首屏体验

- 在现有 `theme.ts` 内扩展或拆分同域 store，避免两个互相争抢 `document.documentElement` 的主题系统。
- 保留原 `travel-notes.theme` 三态键的向后兼容；新增单独且带版本的主题色持久化字段。合法值为预设 ID 或经过严格 HEX 校验的自定义色。无效、旧版、不可访问 localStorage 要平稳回退到山水绿。
- 修改 `frontend/public/theme.js` 以便在 CSS / Vue 挂载之前使用当前外观与色调，避免刷新页面先闪绿再变蓝。同步处理 `<meta name="theme-color">`，但不要把页面主题与浏览器背景颜色直接混为一个值。
- 支持跨标签页 `storage` 同步；`prefers-color-scheme` 变化只改变明暗，不丢掉用户选中的主题色。与用户登录态无耦合。
- 对每套配色在浅/深状态下计算前景、背景和强调色组合。正文普通文字对比度原则上达到 WCAG AA 4.5:1；大文字和关键图标/交互边界至少 3:1。检查实际计算后的颜色，而不是只凭视觉感觉。
- 严格限制输入格式；避免自定义 HEX 造成透明、超长或 CSS 注入；禁止使用未信任 CDN 取主题资源。

### 3.3 UI 入口

- 沿用 `SiteHeader.vue` 右上角设置浮层，在“主题模式”下面新增“主题色调”区。桌面为锚定右上角可滚动面板，手机为不溢出的合适面板。
- 个人主页如需复用相同设置，调用同一组件（例如 `AppearanceSettings.vue`），不要维护第二套状态或样式。
- 图片灯箱/评论侧栏/其他浮层打开时修改主题色，应立即更新其按钮、焦点环与活动状态，且不能破坏模态焦点锁、滚动锁和关闭行为。

## 4. 全站视觉统一（P0/P1）

按审计矩阵而非凭空改版，优先覆盖：

1. **全站框架**：Header、抽屉、底部导航、面包屑、内容容器、Footer，避免某些页面极宽、某些极窄；菜单和当前页状态一致。

4. **专业图片灯箱**：基于**本地最新 M14**代码做适配，保持用户已完成的动画、缩放、旋转、拖拽、工具栏、比例和下载功能，不要从远程 M13 旧版恢复。
