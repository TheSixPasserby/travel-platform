# 项目风险登记表

| 风险 | 影响 | 应对 |
|---|---|---|
| 需求持续扩大 | 无法按期完成 | P0/P1/P2 分级，新需求先评估 |
| 前后端接口不一致 | 联调返工 | 先定 API 契约，统一 DTO/TS 类型 |
| DSH 多代理修改冲突 | 文件覆盖、集成失败 | 明确文件所有权，主代理整合 |
| 偏离约定分工或擅自切换模型 | 职责边界混乱、质量控制失效 | 启动时分别核对 Codex 与 DSH 各自模型，按分工执行；发现偏离先报告 |
| 越权访问 | 安全缺陷 | 所有写接口校验资源所有权 |
| 图片上传风险 | 恶意文件和磁盘风险 | 白名单、大小限制、随机名、路径隔离 |
| Markdown XSS | 脚本注入 | 安全渲染和清理 |
| AI API 不稳定 | 扩展不可用 | 超时、异常处理、核心功能解耦 |
| 本地图片丢失 | 图片失效 | 持久化目录和备份说明 |
| 数据库时间偏移 | 行程日期错误 | 统一 Asia/Shanghai |
| 测试不足 | 答辩演示失败 | 每阶段回归和演示脚本 |
| 学校格式变化 | 材料返工 | 收集学校模板和教师要求 |

工期紧张时先保 P0，再保 P1。P2 可延后或取消，不牺牲权限、安全和基础业务正确性。
