# 需求规格说明书

当前实现对应 M17，更新于 2026 年 11 月 13 日。历史优先级保留，完成范围见 [项目状态](../PROJECT_STATUS.md)。

## 1. 项目概述

系统以 UGC 旅游攻略和行程辅助为核心，面向游客提供内容浏览、发布、互动、目的地查询和旅行计划管理。目的地管理属于 P0，基础后台属于 P1，AI 行程推荐属于 P2 选做。

## 2. 用户角色

| 角色 | 权限 |
|---|---|
| 游客 | 浏览公开攻略和目的地、搜索内容 |
| 注册用户 | 游客权限 + 发布攻略、点赞、收藏、评论、管理个人行程 |
| 管理员 | 平台内容和用户管理 |

权限必须在后端执行，不能只依赖前端隐藏按钮。

## 3. 功能需求

### 3.1 用户与认证

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-USER-01 | 账号密码注册，账号唯一 | P0 |
| FR-USER-02 | 账号密码登录、退出 | P0 |
| FR-USER-03 | 获取当前登录用户资料 | P0 |
| FR-USER-04 | 修改昵称、头像、简介 | P0 |
| FR-USER-05 | 管理员禁用/启用用户 | P1 |

密码使用 BCrypt。登录失败提示不得泄露不必要的账号存在性信息。

### 3.2 攻略

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-GUIDE-01 | 登录用户创建攻略草稿或直接发布 | P0 |
| FR-GUIDE-02 | 标题、摘要、正文、目的地、封面 | P0 |
| FR-GUIDE-03 | 旅行天数、人均预算、季节 | P1 |
| FR-GUIDE-04 | 攻略列表和详情 | P0 |
| FR-GUIDE-05 | 作者编辑、删除自己的攻略 | P0 |
| FR-GUIDE-06 | 管理员隐藏或恢复攻略 | P1 |
| FR-GUIDE-07 | 攻略支持多张正文图片 | P1 |
| FR-GUIDE-08 | 攻略标签 | P1 |
| FR-GUIDE-09 | 作者撤回已发布攻略为草稿 | P1 |

正文保存为 Markdown，当前编辑器采用 Vditor 4.0.1，支持所见即所得、即时渲染和源码模式。展示端必须安全渲染和清理 HTML，不能直接注入未经处理的原始 HTML。

### 3.3 互动

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-INTER-01 | 点赞/取消点赞 | P0 |
| FR-INTER-02 | 收藏/取消收藏 | P0 |
| FR-INTER-03 | 查看个人收藏 | P1 |
| FR-INTER-04 | 发表评论 | P0 |
| FR-INTER-05 | 删除自己的评论 | P0 |
| FR-INTER-06 | 管理员隐藏违规评论 | P1 |

M17 增加两级回复、显式用户提及和站内通知。回复保存根线程及直接目标关系，最多提及五位有效账号。通知按收件人隔离，支持未读、已读及评论定位。评论每分钟最多 10 条、滚动 24 小时最多 100 条。私信和关注关系未纳入当前实现。

### 3.4 目的地

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-DEST-01 | 游客浏览目的地列表和详情 | P0 |
| FR-DEST-02 | 展示名称、地区、简介、封面、推荐季节 | P0 |
| FR-DEST-03 | 目的地关联攻略 | P0 |
| FR-DEST-04 | 管理员新增、编辑、停用目的地 | P0 |

目的地可代表城市或景点，通过 `destination_type` 和可选 `parent_id` 支持简单层级。目的地资料可维护坐标、地址、开放时间、门票与来源，支持图库及城市景点层级。

### 3.5 搜索与分页

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-SEARCH-01 | 标题/摘要关键词搜索 | P0 |
| FR-SEARCH-02 | 目的地筛选 | P0 |
| FR-SEARCH-03 | 标签筛选 | P1 |
| FR-SEARCH-04 | 按发布时间或热度排序 | P1 |
| FR-SEARCH-05 | 攻略和目的地服务端分页 | P0 |

默认 `page=1`、`size=10`，固定要求 page >= 1、1 <= size <= 50；非整数或越界返回 400，不静默截断。准确排序口径见 API 契约。

| 编号 | 需求 | 优先级 |

当前使用本地受管存储，提供 320、640、960 像素衍生图片及原图查看。生产环境上传目录应配置到应用目录之外或持久化卷。

### 3.9 AI 行程助手

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AI-01 | 输入目的地、日期/天数、预算和兴趣 | P2 |
| FR-AI-02 | 生成按天组织的行程建议 | P2 |
| FR-AI-03 | 返回景点建议、理由、预算和注意事项 | P2 |

AI 通过后端调用外部模型 API。密钥由服务端环境配置或管理员独立私有配置文件管理。当前使用外部兼容 API，不训练模型。模型输出必须校验，不能信任模型生成的 ID 或 SQL。

## 4. 核心业务规则

1. 用户账号唯一。
2. 未登录用户不能执行写操作。
3. 用户只能修改自己的攻略、评论和行程。
4. 管理员权限由后端认证上下文判断。
5. 点赞、收藏在 `(user_id, guide_id)` 上唯一。
6. 公开列表只返回已发布、未删除、未隐藏攻略。
7. 目的地停用后不出现在新建选择列表，历史关联保留。
8. 行程结束日期不得早于开始日期。
9. 每日安排日期必须在行程日期范围内。
10. 行程项目排序由服务端校验和保存。
11. AI 结果经用户确认后才写入行程表。
12. 管理员通过专用状态接口治理攻略和评论，不代替作者编辑正文或发布草稿；隐藏攻略的作者不能自行解除隐藏。
13. 用户被禁用后不能新登录，既有登录态也不能继续访问受保护业务。

通用传输、认证资料、状态转换与嵌套资源权限见 [API 契约](06-api-contract.md)。M16 搜索与行程关联、M17 社区消息的补充契约分别见对应阶段 API 文档。

## 5. 非功能需求

- 安全：BCrypt、Sa-Token、后端所有权校验、SQL 参数化、Markdown/XSS 安全、上传白名单和大小限制、密钥不进 Git。
- 性能：服务端分页、合理索引、图片不存数据库、避免 N+1。
- 易用：导航清晰、表单校验、操作反馈、loading/empty/error 状态、桌面和移动端适配。
- 可维护：分层、统一响应异常、API 文档同步、环境配置分离、核心业务自动化测试。

## 6. 第一版不包含

酒店/机票预订支付、订单退款、实时导航、实时交通、自动最优路线、私信/关注、微服务、复杂搜索基础设施、自训练 AI。
