## 3. 可展开的关键设计论证

**角色与所有权分开。** ADMIN能治理公开状态，但不能编辑他人正文、使用作者删除接口或读取他人私人行程。前端隐藏按钮只改善体验，真正约束在Service认证上下文和数据库查询。

**攻略状态机。** DRAFT仅作者私有；PUBLISHED公开；HIDDEN由管理员恢复。发布撤回/编辑/隐藏恢复保留首次发布时间，逻辑删除不在页面复活。子资源的可见性由父攻略公开状态决定，历史互动关系保留。

**并发与真实数据。** 点赞收藏靠联合唯一索引防重，返回实际计数。行程写先锁根、再重读子对象；日期调整与完整排列排序原子完成。实际等待删除测试发现MyBatis一级缓存可能复用旧子查询，根锁显式flushCache后修复。管理员集合有序锁及锁后重核身份，避免两个管理员互禁造成全失效。上述是具体测试驱动的处理，不宣称已证明所有并发或高负载情况。

**图片与安全渲染。** 上传检查类型/大小/解码、随机命名和受管路径；数据库只存路径。Markdown关闭原始HTML并净化输出，链接与图片协议受限；评论/行程纯文本。BCrypt、参数化查询、严格JSON和错误脱敏共同构成已测试边界。

**适度技术选择。** 模块化单体便于毕业设计运行、解释与维护；目前不引入Redis/消息队列/微服务。会话在进程内，重启重新登录；多节点共享会话不在当前承诺中。统计仅四项真实COUNT，不增加冗余计数器或分析平台。

7. 测试与演示：引用实际报告，按[10分钟脚本](24-demo-walkthrough.md)演示。

## 5. 常见答辩问题准备

| 问题 | 回答要点 |
|---|---|
| 为什么不用微服务？ | 当前规模、单人毕业工程与本地验收目标，模块化单体满足需求且部署链路短 |
| 管理员为什么不能改任何数据？ | 角色权限定治理；私人内容与作者行为仍遵循所有权，避免角色扩大隐私访问 |
| 如何防止重复点赞？ | 唯一约束+幂等PUT/DELETE，实际并发测试；前端禁用按钮不是唯一保证 |
| 如何保证排序不丢项目？ | 只接受同一天完整无重复ID排列，在根事务锁内一次更新；失败不部分写入 |
| 为什么隐藏后收藏还在？ | 关系保留但公开闸门屏蔽，恢复后可重新出现，避免破坏用户记录 |
| AI在哪里？ | 选做且未接入，当前全部基础业务无外部AI依赖；不演示不存在的推荐接口 |
| 测试能证明性能好吗？ | 不能。现有测试验证功能/权限/特定并发，未给出负载与性能结论 |
| 已经部署了吗？ | 已做本机JAR+生产dist演练；正式公网域名/TLS部署尚无目标，不能说已上线 |
