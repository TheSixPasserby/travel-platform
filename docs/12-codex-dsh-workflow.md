# Codex + DSH Subagent 协作流程

## 角色
Codex 主代理负责需求/架构、任务分配、接口和数据模型决策、整合、测试和状态维护。DSH 子代理负责边界明确的独立任务，并返回证据和风险。

## 模型（双模型协作）
采用双模型协作，两类模型不同是有意设计，不是配置错误：
- Codex 主代理：**GPT-6.1-Sol / Ultra**，负责总体规划、架构决策、任务拆分、代码整合、质量控制和最终验收；
- DSH Subagent：**CodeBuddy DeepSeek V4.1 Flash / Max**，承担编码、测试、文档整理和专项审查。
涉及架构、数据库、API 和跨模块的修改，最终由 Codex 决策。启动时分别核对两侧所属模型，各自符合分工即可，无需相同；不得擅自切换被指定的模型，也不修改 Codex 全局模型配置。若无法核实 DSH 子代理的指定模型配置，应报告并暂停派发该子代理，不得假称一致。

## 推荐并行方式
设计阶段可并行进行只读需求审查、数据库审查和 UI 页面审查，由主代理统一修订文档。
开发阶段先固定 API、实体和模块边界，再委派独立业务域、独立页面或测试任务。

## 并发规则
不要让多个代理同时修改同一 DTO、Entity、Mapper、路由文件、全局样式或共享配置。主代理检查 diff、构建和测试。

工具返回权限或凭据围栏拒绝时，DSH 停止处理该文件并上报；禁止换工具绕过。主代理仅在自身已有授权和可用工具权限内接管，交付报告须如实保留该偏差。

## 子代理交付格式
1. 完成内容；
2. 修改文件列表；
3. 关键设计决定；
4. 实际执行的测试及结果；
5. 未解决问题；
6. 需要主代理整合的内容。

## 不使用子代理的情况
简单修改、高度耦合任务、需要立即统一决策的任务，或 DSH 不可用/无法核实 DSH 指定模型配置时。
