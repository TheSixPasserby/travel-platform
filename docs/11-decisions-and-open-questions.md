# 决策记录与待确认事项

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-001 | Vue 3 网页端 | 用户已确认 |
| ADR-002 | 现代旅游平台 UI | 用户已确认 |
| ADR-003 | TypeScript | 类型约束和维护 |
| ADR-004 | Java 21 + Spring Boot 3.x | 稳定且适合项目 |
| ADR-005 | MySQL 8.x | 关系型业务数据 |
| ADR-006 | MyBatis-Plus | 降低 CRUD 工作量 |
| ADR-007 | Sa-Token | 简化认证和角色校验 |
| ADR-008 | 模块化单体 | 避免微服务复杂度 |
| ADR-009 | 本地图片存储 | 简化第一版部署 |
| ADR-010 | AI 使用外部 API | 不训练模型 |
| ADR-011 | 手动行程优先 | 控制工作量 |
| ADR-012 | 双模型协作：Codex 主代理保留 GPT-6.1-Sol / Ultra，DSH Subagent 使用 CodeBuddy DeepSeek V4.1 Flash / Max | 用户 2026-11-02 明确要求，取代此前“Codex/DSH 使用同一模型”的旧要求；两者模型不同为有意设计，不修改 Codex 全局模型配置 |
| ADR-013 | 个人资料修改为 P0，目的地管理 P0、基础后台 P1、AI P2 | Codex 按 AGENTS 优先级消除需求和概述中的冲突，未删除 P0/P1 |
| ADR-014 | satoken 请求头；整数业务码；JSON ID 为字符串；分页 size 最大 50 | Codex 固定跨端契约，减少认证、精度和分页联调歧义；详见 API 第 11–12 节 |
| ADR-015 | 作者修改内容，管理员通过专用接口治理状态 | Codex 按需求收敛原 API 的管理员代改/代发布权限；隐藏内容不可由作者自行重新发布 |
| ADR-016 | ID 使用 signed BIGINT，不保留 view_count；初始化脚本不固定数据库 | Codex 对齐 Java Long、删除无明确需求的冗余计数，并防止既有实例测试时误切业务库 |
| ADR-017 | 优先检查已有 MySQL 实例（历史选择，已由 ADR-018 取代） | 用户先选择已有 8.x 实例；只读查询确认本机实际运行 26.7.0，不能作为 8.x 验证环境 |
| ADR-018 | 准备独立 MySQL 8.4 环境，保留现有 26.7 服务 | 用户 2026-11-02 明确授权；独立端口、数据目录与应用账号，连接凭据只存本地 |

2026-11-02：ADR-013–016 属于主代理在已授权技术基线内的工程裁定；接口与数据库规则尚不代表功能已实现或测试已通过。完整审查结果见 `docs/13-baseline-review.md`。

## 待用户确认
1. 学校最终提交和中期检查日期；
2. 指导教师是否有指定数据库、页面或论文格式；
3. 必须公网部署还是本地演示；
4. AI 服务商/API；
5. 项目品牌名、Logo 和文案；
6. 管理后台是否为硬性验收项。

## 主代理可自行决定
兼容稳定补丁版本、包名、组件命名、具体目录、合理测试工具和小范围 UI 细节。记录在项目文档中。

## 必须先报告用户的变更
更换前后端框架或数据库、改为微服务、引入 Redis/消息队列/搜索引擎、加入支付/地图/第三方登录、删除 P0/P1、改变双模型分工或擅自切换 Codex/DSH 的指定模型。
