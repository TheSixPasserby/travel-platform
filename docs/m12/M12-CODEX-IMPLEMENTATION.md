## 2. P0：将首页改为旅游内容「发现」主页

### 2.1 产品结构

- 将首页从纯静态介绍页转换为真实内容驱动的**发现流**：上方保留轻量品牌氛围和搜索/发布入口，主体展示已发布攻略卡片；不再把三块静态功能介绍作为主要内容。
- 顶栏延续 M10 的单行模式；桌面端提供「发现 / 攻略 / 目的地 / AI 行程」快捷导航，移动 Web 精简为菜单、Logo、设置、用户/登录。不要出现双层 Header。
- 发现区域有简单可解释的分组：**推荐 / 最新 / 热门**。后端已存在 `latest` 与 `popular`；推荐可第一版使用真实数据的确定性排序（近期内容、点赞、收藏等），如需新接口先形成明确的排序契约和回归测试。**绝不虚构推荐算法或参与度**。
- 添加旅行主题/城市入口，例如成都、杭州、大理等，数据必须来自已有目的地或标签 API；不能把硬编码静态城市假扮线上动态推荐。
- 核心内容包括：封面、标题、作者头像和昵称、灰色 `@username`（空间合适时）、点赞数、目的地标签；天数/人均预算/主题按有数据时展示。缺失项自然隐藏而不是展示一排「未知」。

### 2.2 卡片流与瀑布流

- 借鉴小红书卡片/瀑布流的信息密度与内容优先原则，但保留**山水间独立配色、圆角、字体与品牌**。
- 小屏：双列或单列要依赖真实可用宽度判断，**360px 宽度以可读性与触摸为优先**；中等屏 2–3 列，宽屏 4–5 列，避免超窄卡片。
- 图片使用比例占位和懒加载，避免内容流布局跳动。图片失败显示可读占位。
- 瀑布流不能牺牲键盘浏览、屏幕阅读器和 DOM 阅读顺序；可使用稳定 CSS Grid/Columns 等，但要确保可访问性与滚动行为。不要因为追求动画引入重依赖。
- 支持分页或「加载更多」，请求具有加载、错误、重试、空列表和竞态保护。
- 卡片点击进入详情；卡片上的点赞/收藏若做快捷操作，则必须阻止错误嵌套链接、遵守登录和权限、保持请求失败回滚。

### 2.3 统一攻略列表

- 改造 `/guides`，与首页共用可复用的卡片、筛选和分页能力，不复制两份搜索逻辑。
- 保留已有关键词、目的地、标签和最新/热门排序，URL Query 可恢复筛选、分页后退与刷新状态。
- 搜索范围只宣称实际支持的内容。若想加作者搜索或联想，应新增明确后端能力与测试，不能靠前端假筛选。

## 3. P0：攻略详情转为高质量「旅行笔记详情」

- 大图/图文阅读优先，标题与作者信息层级明确；支持桌面宽阅读区域和侧栏/底部互动布局，手机浏览器无水平滚动。
- 作者资料卡：头像、昵称、`@username`、发布时间，点击进入公开创作者主页；隐藏无有效来源的 IP 属地文本。
- 点赞、收藏、评论入口与数量更醒目，原有 CRUD/权限/竞态保护完整保留。
- 正文继续使用安全 Markdown；旧三篇攻略及历史用户稿件正常渲染。
- 目的地与景点关联提供清晰可点击入口；文章尾部加入「你可能也喜欢」：先做**真实且可解释的相关内容检索**（相同城市/相同标签/时间热度），排除当前文章、未发布/隐藏、无权查看的内容。不允许编造相关推荐卡片。
- 未登录读者允许浏览已发布内容；互动动作按现有登录规则提示；草稿/隐藏的权限不变。
- 可增加复制链接/原生 Web Share（浏览器支持时），但不要声称已具备外部社交平台发布功能。

## 4. P0：全站可点击图片灯箱预览

### 4.1 覆盖范围

- 文章详情封面、正文内图片、文章图库；城市/景点详情封面与图库；编辑器内上传图片预览（编辑器自身冲突时谨慎处理）。
- `GuideCard` / `DestinationCard` 的卡片整体以导航为主，**不要强行把卡片封面点击改成灯箱**，导致无法进入详情。灯箱默认作用于详情页与图库。

### 4.2 交互规范

- 点击/键盘可打开大图，黑/半透明遮罩，适合大图的 contain 模式、加载状态、错误回退、图片说明与第 N / M 张。
- 多图时支持上一张/下一张、← →、Esc 关闭、移动端滑动；提供关闭按钮和必要的屏幕阅读器标签。
- 支持放大查看（库自带或简单可靠的缩放实现即可），禁止复杂手势导致页面卡死。
- 打开后焦点进入弹层，关闭时焦点回到触发点；锁定背景滚动，组件销毁/路由变化时彻底清理监听器与滚动锁。
- 图片只接受已在页面中通过可信数据渲染的资源，不接受客户端自由传任意 URL 做 fetch 或绕过 Markdown 安全白名单。
- 优先复用成熟稳定的轻量灯箱库（经许可证、版本、安全性与实际兼容性确认），若自己实现必须有等价测试。
- `SafeMarkdown` 当前使用清理后的 `v-html`，可在已验证的图片元素上使用事件委托；**不能为了加点击事件关闭 DOMPurify、允许任意 HTML 或任意外部图片**。

## 5. P0：接入成熟可视化文章编辑器（Vditor 优先）

### 5.1 选型与技术边界

- 不再自研简化富文本编辑器。优先集成 **Vditor**（<https://github.com/Vanessa219/vditor>），先核验当前正式版本、许可、样式资源、Vue 3/Vite 兼容性并锁定经测试的 npm 版本与 lockfile。
- 使用官方支持的 `wysiwyg`、`ir`、`sv` 三种模式：默认 **所见即所得**；Markdown 源码模式与即时渲染模式作为可选切换。首要目标是普通用户不必掌握 `#`、`![]()` 等语法。
- 新建可维护的 `GuideRichEditor.vue` 封装，管理组件挂载、卸载、内容同步、主题、禁用态、上传与错误提示；`GuideEditorView.vue` 保留攻略元数据/发布状态/图片图库/景点/标签的业务职责。
- **继续使用 `guides.content` Markdown 字符串及现有 API**，不因为换编辑器就切换存储 HTML 或重新创建文章表。
- Vditor 的资源应随站点构建并同源部署/自托管，不能让核心编辑器依赖默认公共 CDN；按官方资源加载机制核验实际网络请求，离线/无 CDN 网络环境应能使用。
- Vditor 默认本地缓存**显式关闭**（如 `cache.enable: false`）以避免跨账号/跨文章数据混淆；必要时可另做以用户+文章 ID 隔离、可审计的草稿机制，但不是本轮 P0。

### 5.2 编辑能力

- 标题层级、加粗/斜体/删除线、有序/无序列表、引用、链接、表格、图片、撤销/重做等；仅启用本站读者端安全支持的能力。
- `SafeMarkdown` 不支持的插件语法、任务列表、嵌入 HTML、动态图表/视频等不能悄悄输出后丢失；需明确禁用或补充严格、安全的渲染与测试。
- 可视化/即时渲染/源码三模式切换后，标题、链接、引用、列表、表格、受管图片和文字应保持意义与结构；无法无损转换的复杂旧文档须提示并提供源码回退，**不得静默覆盖或重新格式化成空白内容**。
- 图片按钮、粘贴和拖拽上传应通过已有 `/api` 受管上传路径与 Token 校验；限制单图类型 JPG/PNG/WebP、5MB 和当前 20 张图库业务上限，使用与当前业务一致的错误反馈。不能让编辑器把 Base64 图片或 `blob:` URL 直接保存到文章，不能偷用编辑器默认外部图床。
- 编辑器插入图片和图库关联需要一致性策略：避免同一张图重复插入、避免重载后图库与正文意外失联；删除正文图片不应悄悄永久删除图库或磁盘文件。
- 支持当前已实现的摘要、封面、城市、景点、旅行天数/预算、主题、保存草稿、发布、撤回、编辑隐藏稿规则；网络失败、保存进行中、跨账号切换都不会破坏内容。
- 保留未保存更改离开确认机制；**草稿不自动公开**。
- 深色模式三态、窄屏触控、输入法编辑、粘贴纯文本与 Word/HTML 时的安全清理、聚焦、Tab/键盘操作都需验收。

### 5.3 兼容性验证

- 使用已有三篇 M8 攻略及人为构造的综合 Markdown 样例，记录**加载 → 模式切换 → 小幅修改 → 保存 → 重新打开 → 渲染**结果。
- 测试内容覆盖：标题、多段落、列表、链接、引用、表格、中文标点、换行、代码块、正文受管图片与 alt、100000 字符长度限制和 20 张图库上限。
- 存在已发布/草稿/隐藏状态的旧记录必须保留 ID、作者、发布时间和互动数据；只修改用户明确保存的字段。

## 7. P0：未启用 IP 属地的真实处理

- 当前服务端字段存在，但 GeoIP 未接通。**界面不再统一展示「IP 属地：未知」**，对 null、空、`未知`、本地测试标记等非有效归属地隐藏。

- 当存在少数已验证有效的属地文本时，可按产品决策允许展示；本轮默认采用**全局禁显开关**，直到来源能力真实验收。前后端测试应覆盖历史记录与未配置数据源。

## 9. UI/UX 统一规范：借鉴机制，保留山水间品牌

- 信息层级以图文内容、真实作者、地点标签和互动为主，不再大面积用抽象占位插画占据首页主位。
- 继续使用松绿/奶油白/深墨绿的现有主题 Token；深色模式不能只是整体颜色反转，要考虑图片、浮层、文本对比度。
- Header 继续单行；移动 Web 抽屉保留；新增发现流不需要重新设计登录/权限/后台。
- 主要按钮 44px 左右可触摸，状态明确。内容卡片不要把所有文案塞满，卡片标题应优先于辅助信息。
- 页面过渡、卡片 hover、弹层动效轻量，遵守 `prefers-reduced-motion`。
- 不复制第三方品牌的色彩组合、商标、宣传语、专属图标和原有平台的版权内容。
- 缺少图片、作者、标签或推荐数据时展示合适空状态；不造“10000+ 浏览”“百万热门”类虚假指标。

## 10. 不做清单（保护时间与质量）

不在本轮引入：复杂个性化推荐、机器学习推荐、关注/私信/消息、支付、第三方登录、直播、短视频、带水印素材抓取、站外内容搬运、Web 端全站重写、后端微服务、未经授权的爬虫、全新数据库体系、真正的 Android/iOS/微信上线。

用户既有 **AI 行程**功能、城市/景点、攻略、互动、用户、后台必须继续正常工作。真实 AI 供应商 Key 若未配置，不要用假调用伪称已联调。
