# M16 实际接口与迁移说明

以下为已落地契约。实施包中的 `M16-API-DATA-CONTRACT.md` 保留为原始输入，建议接口与最终差异以本文件为准。所有 JSON API 沿用 `{code,message,data}`，ID 在 Web 契约中为字符串。

## 公开跨类型搜索

`GET /api/v1/search`，匿名可读。

| 参数 | 约束 |
|---|---|
| `keyword` | trim 后最多 100 个 Unicode 码点；空值返回空列表 |
| `kind` | 可省略，或 `GUIDE / CITY / SCENIC_SPOT / CREATOR / TAG` |
| `sort` | `relevance` 默认，或 `latest` |
| `size` | 1–50，默认 24 |
| `cursor` | 上页 `nextCursor`，绑定 keyword/kind/sort，客户端保持不透明 |

```json
{"code":0,"message":"success","data":{"records":[{"kind":"CITY","id":"2","title":"成都","subtitle":"四川省","coverImageUrl":"/uploads/2026/11/example.jpg","username":null,"href":"/destinations/2"}],"nextCursor":null,"hasMore":false}}
```

示例说明结构，实际 ID、文案和图片由数据库返回。`coverImageUrl`、`subtitle`、`username` 可空。单个游标覆盖全部类型，Web 将本次已加载结果按类型分组，不伪造每组总数。

- 数据库 UNION 查询与 keyset 分页，参数绑定并转义 LIKE 通配符；没有增加搜索服务或依赖。
- 相关性依次为标题精确、标题包含、关联公开字段匹配；之后按时间、类型和 ID 稳定排序。最新排序忽略相关性分值。游标带首屏时间快照，并逐页重新校验公开状态。
- 攻略限已发布、未删除且作者有效；景点和父城市均有效；作者仅返回已有公开资料，允许尚无作品的有效作者；话题须有关联公开攻略。收藏、私人行程、草稿、账号权限字段不进入搜索。
- 结果链接为真实站内攻略、目的地、公开作者及话题筛选路由。非法分类/排序/size、过长关键词、错配或损坏游标返回 HTTP 400 / `40001`。空白 kind/sort/cursor 视作未传。
- 输入建议复用此接口 `size=6`。Web 本地历史最多八条，可清空；250ms 防抖、取消旧请求、IME 组合输入与键盘导航由 `SearchBox` 处理。

## 攻略关联景点原子加入行程

`POST /api/v1/itineraries/guide-imports`，要求当前有效登录用户。客户端不传目标所有者 ID。

加入已有行程：

```json
{"clientRequestId":"13c6618e-7aef-49a9-a89d-76d89b380a25","guideId":"4","destinationIds":["26","27"],"itineraryId":"3","dayId":"5","newItinerary":null}
```

新建并加入：

```json
{"clientRequestId":"13c6618e-7aef-49a9-a89d-76d89b380a26","guideId":"4","destinationIds":["26","27"],"itineraryId":null,"dayId":null,"newItinerary":{"title":"成都慢行","startDate":"2026-11-20","endDate":"2026-11-22","travelDate":"2026-11-21"}}
```

响应 data：

```json
{"itineraryId":"3","dayId":"5","added":["26"],"alreadyPresent":["27"]}
```

- UUID 必填；`destinationIds` 为 1–20 个不重复的正整数 ID，仅可使用攻略真实关联的、有效且归属攻略城市的 `SCENIC_SPOT`。源攻略和作者须仍可公开访问。
- `newItinerary` 与已有 `itineraryId + dayId` 二选一；新建城市取自攻略，日期/标题及每日 100 项、整单 500 项限制复用既有服务校验。目标须属于当前用户且为有效未归档行程，day 须属于该行程。
- 同一事务内创建根/天/全部项目/回执，任何一个项目失败均整体回滚。既有行程按当天 destination ID 去重，保留原项目和排序，新增项目追加到末尾。`added/alreadyPresent` 都返回景点 ID。
- 当前用户行锁、目标行锁、地点有序加锁和数据库 `(user_id,client_request_id)` 唯一约束支持多实例串行化。UUID 和请求哈希共同约束幂等：相同请求返回同一已提交回执；相同 UUID 改变内容返回 409。网络失败重试沿用 UUID，用户修改意图后生成新 UUID。
- 回执表达过去已经提交的动作；随后用户归档或逻辑删除目标，重放相同请求仍返回原结果且不再次写入。新请求继续校验目标可写状态。硬删除受既有外键级联语义约束。
- 400 / `40001`：参数、未关联/停用景点、日期或容量不合法；401 / `40101`：匿名或失效登录；403 / `40301`：非本人目标；404 / `40401`：不可访问的源/目标/日期；409 / `40902`：归档状态或幂等意图冲突。未预期异常沿用统一脱敏响应。

## AI 来源与草稿恢复

既有 AI 能力、生成/单日重生成和完整行程导入 API 保持原契约。新增的是 Web 内来源状态与恢复机制：

- 收藏页先读取攻略详情，详情/抽屉只能把真实城市与用户选中的景点传入需求表单，预填 `cityId/preferredIds`；`mustVisitIds` 由用户编辑确认。
- 来源 chip 保存公开攻略 ID/标题、城市与所选地点，按当前账号隔离；sessionStorage 最长 30 分钟，切换账号/令牌或退出清理；存储不可用仍允许当前内存流程。
- 工作台草稿按账号在当前浏览器会话保存，最长六小时、序列化长度上限 2,000,000 字符，读取时检查结构。刷新后明确选择“恢复”或“丢弃”，不会静默替换用户正在编辑的需求或预览。
- 新来源须明确应用；同一篇攻略更换地点选择也会更新偏好。生成只产生预览，经编辑和确认后才调用既有幂等导入。保存后路由失败重试保持原 UUID。
- AI 关闭、服务不可用或未配置时，可用同一真实地点抽屉完成手动创建/添加。来源不是生成结果，页面不显示假 AI 行程。
- 前端生成请求传需求参数和 ID。既有后端会加入受限的公开城市/景点资料和同城已发布攻略摘录（每篇最多 1600 字符），页面在生成前说明此范围；私人行程、私密收藏和密钥不发给模型。

## 受控图片衍生尺寸

`GET /uploads/{managed-path}?width=320|640|960`，原路径不带 width 时保持原始字节。非法 width 返回 HTTP 400，受管路径校验失败返回 404。

- 仅处理现有受管本地图片，不接收外部 URL。源文件最大 5MB、边长 10000、2500 万像素；两路解码并发、等待最长两秒，先降采样再缩放，尺寸受三档白名单约束。
- 正确应用 JPEG EXIF 方向 1–8，衍生图不带源元数据；透明图输出 PNG，普通图输出 JPEG。原图完全保留，M14 灯箱和下载仍使用原 URL。
- `travel.storage.thumbnail-dir` / `THUMBNAIL_DIR` 可配置独立缓存目录，默认 `./.local/image-variants`。缓存键含真实路径、文件大小、修改时间、宽度与算法版本，原子写入。实际缩略图和直接原图缓存一年；生成受限/失败时回退原图，缓存 60 秒便于恢复后重试。
- 卡片使用 srcset/sizes、固定比例、懒加载与异步解码；衍生图失败只尝试原图一次，再显示既有占位和 alt。图库与正文安全白名单保持原行为。

## 数据库增量与应用回退

新增 `database/migrations/V016_01__guide_trip_imports.sql`，fresh schema 同步增加 `itinerary_guide_imports`。新增表保存 user/request/hash、目标根/日期和历史响应，唯一键防重复；不修改原十四张表结构，不清理任何业务记录。

本轮只对隔离自动化测试库与 `travel_platform_m16_6829168b_test` 浏览器验收副本执行；原业务库尚未迁移。恢复副本在迁移前验证十四张表、290 行与 44 个上传文件一致。迁移重复执行后结构与原表数据保持一致。

运行新功能前，由操作者明确选择已备份并完成恢复验证的目标库，只执行本次增量文件；不得在非空库重跑 `schema.sql`。现有启动器不会自动迁移。未迁移的库不能使用新行程导入端点。回退旧应用时保留新增表及幂等回执，旧代码可忽略该表，不自动 DROP。缓存为可重新生成文件，与上传原图独立。
