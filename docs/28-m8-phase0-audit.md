| AI | 仅文档中存在概念 | 配置、检索、兼容API客户端、结构/业务校验、限流、预览/编辑/单日重生成/保存与降级全部待做 |
| UI | 暖白/自然绿设计、自定义组件、loading/error/empty、图片占位、响应式 | 城市详情下属景点、景点资料/图库、后台扩展、攻略多景点选择、AI工作页 |

关键实现证据：`DestinationService.checkParent()` 只验证父存在/状态和循环，没有父类型约束；publicList 仅 ACTIVE，publicDetail 保留 INACTIVE 历史详情，这一既有行为继续兼容。`GuideService.update()` 为完整替换，正文、图片、标签同事务，**不能直接构造局部 PUT**，否则可能清空未提供字段。`ItineraryService.create()` 只创建根，每日/项目是独立事务；跨多次 HTTP 请求无法整体回滚。

## 4. 数据保护与实施风险

1. **迁移机制缺失**：schema.sql 仅初始化。新增迁移必须单独文件、元数据前置检查、校验已有列定义、重复执行与副本验证。MySQL DDL 存在隐式提交，不能把整个升级包装成“事务可回滚”。
2. **备份恢复未演练**：本轮未制作可恢复 SQL/uploads 成套备份，未执行恢复。Phase 1 首次内容写入前，暂停本项目写入、备份两者并恢复到全新隔离副本；Phase 2 再在该副本验证迁移。原测试库不得被覆盖成开发库副本。
3. **未知用户保护**：第四名用户及头像完整保留。不得按 demo 前缀以外规则清理任何数据，不把整个开发库当测试夹具。
4. **内容并发覆盖**：Phase 1 内容包记录原内容摘要和受保护字段；写前再次核对 ID/作者/状态/发布时间/updated_at，发生漂移立即停该篇，提供差异。写后对不应变化的字段和互动关系做精确比较。
5. **照片真实性/许可**：当前没有可用于攻略的照片。未完成照片来源、作者、许可、许可链接和获取日期核查；不能把官网图片可查看当作可转载授权，也不能以生成照片冒充实地摄影。
6. **父类型新规则兼容**：先扫描已有层级异常，未知记录不自动归类或重挂。本轮六城无异常。停用城市保留历史关系，但 AI/新建关联须同时检查城市与景点可用。
7. **AI 真实性和费用**：目前零景点，不能真实生成。只读检索已发布攻略和可用景点；先 mock/stub 完整验收。供应商、Base URL/Model/Key 和实际费用未确定，真实模型调用另行征得同意。
8. **缺 CI 与独立 lint**：本地等价命令已实际执行；后续补 CI 并配置专用 MySQL8.4 测试库。没有执行的 lint/浏览器验收不写成通过。

备份操作将仅使用已确认的本机项目库和安全客户端配置，以独占新文件保存 `mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF`，不含 `--databases`，避免恢复 SQL 内嵌 USE 指回原库。SQL 与 uploads 存于本地 700 目录/600 文件，记录 SHA-256、实例/库名/时间、表数和引用；备份失败即停止写入计划。恢复先到新的空 `_test` 库与独立 uploads 目录，复核完整记录/登录/权限/图片，绝不导回已有库。生产环境、破坏性回滚和外部发布均不在当前授权范围。
