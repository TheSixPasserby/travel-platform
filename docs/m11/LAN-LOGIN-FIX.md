本页为历史阶段记录，日期、测试数量和当时范围按原记录保留。当前使用与开发入口见 [项目文档](../README.md)。

2026-11-11。用户从 `http://192.168.1.200:5173` 登录时，后端返回403和 `Invalid CORS request`。对同一接口使用 localhost Origin 则能进入参数校验，定位为运行中的旧后端未接受当前LAN来源。

`./start.sh`此前只检查HTTP健康、TCP和LAN监听，复用旧后端时没有核查其启动时的CORS配置。本次将期望Origin计算提前，并对后端发送无凭据OPTIONS预检，精确核验允许来源、POST和content-type/satoken。旧配置不符时明确提示重启，不会假报就绪或自动停止未知服务；新启动后也核查。

已核对旧Java进程归属并优雅重启后端，Web保留。通过真实浏览器在上述LAN地址使用已有演示账号登录，返回200并进入个人中心。后端直连预检200、LAN同源POST能够进入业务校验，未知Origin仍403；Vite对自身OPTIONS返回204，与应用同源POST流程无冲突。全Python91项通过，Bash和diff检查通过。后端/前端源码未改，无需重跑其构建。

真实浏览器只能验证这台机器使用LAN地址的端到端链路，未声称已操作用户的另一台物理设备。用户刷新原页面后重新登录即可。
