# M13｜DSH 前端主责实施说明

本轮用户明确指出 M12 前端简陋、信息密度不足、瀑布流有空洞，希望 **DSH（CodeBuddy DeepSeek V4.1 Flash / Max）主要负责前端设计与具体编码**；Codex 主代理负责接口、安全和质量验收。务必先检查实际运行时工具/模型是否如指定，不得把只读审查算成“DSH 实现了页面”。

## 交付品质与交互期待

参照 `references/` 8 张自制设计稿和用户三张问题截图，**自拟更好的布局细节允许，实用性优先**。不要逐像素临摹参考图，更不要照搬他人平台的 Logo 和完整 UI 皮肤。使用山水绿/自然白双色主题，准确的中文排版、合理的层级、统一的图标库、富于质感的细节与克制的动效。

在每一阶段实际提交可审查源码改动、单元测试、真实 1440/390 截图，说明设计差异。

### F1. 无限瀑布流 [P0]

重点文件：`GuideGrid.vue`、`GuideFeed.vue`、`GuideCard.vue`、`useGuideFeed.ts`、`HomeView.vue`、`GuidesView.vue`、`CreatorView.vue`。**不许保留按行排版制造的上下空隙**；多列密铺真实图片，不以缩短卡片高度掩盖问题。取消公共内容页的页码按钮，IntersectionObserver 触发下一批追加，支持断网重试、最后一页结束、账户/筛选切换防竞态、后退恢复和无障碍的手动退路。JS 虚拟化或 CSS columns 方案先评估布局稳定性和焦点/阅读顺序。

### F2. 右侧互动栏与评论抽屉 [P0]

改造 `GuideDetailView.vue` 并拆分 `ArticleActionRail.vue`、`CommentDrawer.vue`（命名可调整）。阅读区不要缩成短视频竖屏；右侧竖列放点赞/收藏/评论/分享/作者，评论按钮控制右侧抽屉，移动端全高适配。复用 `GuideActions.vue` 的真实 interaction 状态以及 `GuideComments.vue` 的真实评论逻辑，不重写 API 副作用。关注/楼中楼/评论点赞若无后端就**不画伪功能按钮**。关闭抽屉保留正文位置和评论草稿，键盘 Tab / Escape / focus trap，屏幕阅读器语义正确。

### F3. 作者个人主页 [P0]

沿用已有 `/users/:username` 路由和 `CreatorView.vue`，做成有作品、有身份、有个人风格的创作者主页。全站所有作者头像/昵称都能点击到公开主页，自己登录后点击头像进自己的主页；原资料编辑页下沉到设置。公开/私有界面按用户身份区别显示。自制截图的点赞、收藏和粉丝数字都是示意，必须绑定真实数据或删除。

### F4. 动效系统 [P0]

给 Header、路由、瀑布流进入、滚动追加、图片 hover、头像 hover、点赞收藏、评论抽屉、灯箱、表单、设置弹层提供统一 tokens 和微交互；`prefers-reduced-motion` 下禁用非必需动效。时长与设计稿一致，不用背景粒子、不动整个网格、不重排已加载卡片。动画跑在 transform/opacity 上，真实 Chromium 浏览器录制/时间点截图验收。

### 交付前自检

- 所有前端受影响测试通过 + Vite/TypeScript build；交付浏览器截图必须是真实运行站点，而不是编辑设计稿。
- 360/390/430/768/1024/1440/1920px 验证无水平滚动、无固定组件遮挡、无瀑布流大空洞。
- 匿名/作者/普通用户，点赞收藏和评论失败处理，评论草稿、返回列表滚动、动态多图、图片加载失败、Reduced Motion 都验证。
- 公开 API 不泄露私人草稿/收藏/行程。未经用户授权不提交/推送。
- 禁止复活 `deprecated/uni-app/` 代码或工作流；Vditor 和 AI 已有功能保留。

DSH 实际执行失败时回报准确原始错误、文件更改数量和测试情况；Codex 决定是否接替，**不允许冒称已由 DSH 实现**。
