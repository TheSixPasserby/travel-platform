## 2. 产品方向与设计原则（P0）

定位：**旅行攻略分享 + 图文社区 + 目的地探索 + AI 行程规划**。借鉴小红书的图片笔记发现/双列瀑布流、Bilibili 的评论/作者生态、贴吧的讨论层级、X 的轻量实时交互、Instagram 的沉浸图片阅读，但绝不复制品牌 Logo、独特视觉资产或逐像素复刻。保持“山水间”自然、现代、克制的山水绿品牌气质。

视觉要求不是加一堆边框和渐变：更紧凑的内容密度、明确的功能层级、细腻的间距、统一的图标、合适的字体、图片与文字比例，合理利用大屏；深浅双主题对比度充分；正文可连续阅读。桌面保持既有单行 Header，但可重构导航结构与内容侧边栏，使发现、搜索、发布、账号、设置更自然；手机浏览器保持高质量适配，与 uni-app 归档完全不同。

**设计先于铺代码**：DSH 先对照 01—08 图确定 design tokens、组件布局分区、动画规格、响应式断点，再开始按页面重构；必须产出前端实际文件、浏览器截图和差异说明，不能只交一张“效果图”就结束。

## 3. P0：真正的瀑布流 + 无限滚动

适用：`/` 发现流、`/guides` 公共攻略流、`/users/:username` 公开笔记流；必要时我的公开笔记页也可复用统一组件。**公共文章发现不再出现页码和上一页/下一页**；后台审核、管理表格等无需强行改成瀑布流。底部允许在自动加载不可用或连续失败时出现可访问的“加载更多/重试”按钮作为退路，但不恢复传统翻页。

### 真正解决卡片空洞

- 不采用普通 CSS Grid 以行高对齐的伪瀑布流，也不直接依赖尚非 Baseline 的实验性 `grid-lanes/masonry` 语法；评估跨 Chrome/Safari/Firefox 都能运行的方案。可使用带 ResizeObserver 行跨度的稳定网格或经过评估的 CSS columns/均衡列算法，权衡 DOM 顺序、键盘阅读顺序、图片异步高度和追加卡片时是否出现列跳动。**选择方案须在技术说明中写明取舍，并以真实截图验收列内无大空洞。**
- 断点示意：手机约 2 列、平板 2—3 列、桌面 4 列，大屏视宽允许 4—5 列；不能强制手机卡片像素过窄。卡片具有合理的图片宽高比与文字截断，作者/点赞底部不因长用户名溢出。固定尺寸占位或 `aspect-ratio` 预留空间，图片解码后不允许大片 CLS。
- 原有卡片可复用 `GuideCard.vue`，布局适当紧凑；卡片封面/标题进入文章，作者头像与昵称去作者主页，互动数量真实。避免外链嵌套、不可点击区域、阴影泛滥。

### 真无限滚动的数据要求

- 首次加载约 12 条可参考当前基线；用 `IntersectionObserver` 接近列表底部预取下一批，**append 到既有数据**，不替换已有卡片；列表结束明确显示“已经看完”；失败允许原位置重试，不能无穷请求。
- 同一时刻最多一条下一页请求；网络竞态、快速切分类、搜索、离开路由、账号切换时取消或忽略旧请求；ID 去重；保证服务端排序稳定 (`publishedAt + id` 等有唯一 tie-breaker)，若 offset 翻页在插入新文章时不稳，评估并实现可兼容的游标分页。不要假设 cursor 已存在，Codex 负责最终 API 契约和后端兼容。
- 返回列表保留滚动位置、筛选/关键词/排序及已加载数据（合理上限的短期缓存，需防止跨账户私有数据泄露）；新筛选从首批加载重新开始。历史记录可回退，直接分享 URL/刷新能恢复查询语义。
- 使用 `rootMargin` 预加载但避免自动连发；长列表在必要时评估虚拟化/窗口化，不能让 500 张图成为无界 DOM；首次加载、追加、图片失败、空结果、网络断开、无 JS Observer 支持均有降级。
- 从本机 20 篇公开攻略的历史验收资料出发，必须实际验证**第一批 12 篇 + 后续至少 8 篇**的连续加载（以当前真实数据为准，不假定项目库永远 20 篇），无丢失/重复，底部无数字分页。

## 4. P0：文章详情页重构为沉浸阅读 + 右侧互动栏

参考 03、04 两张。桌面版：中间主要图文阅读（宽度建议约 700—820px），右侧贴近正文有独立的竖向浮动/粘性操作组，包含点赞（真实状态/计数）、收藏、评论（计数/打开抽屉）、分享（复制文章链接/Web Share 能力检测）、作者头像（链接个人主页）。不需要强制给“换一篇”等未经授权的动作；相关推荐使用当前真实 API。右侧按钮图形、文字与触达尺寸统一，滚动中动作可见但不遮挡正文。

点击评论：桌面右侧展开约 380—460px 宽的评论抽屉，**正文与抽屉尽量并排**，而不是移动到遮挡正文的大型居中弹窗；视宽不足则按可用空间自动切换叠加的右侧抽屉。侧栏顶部固定评论数/排序/关闭，评论列表自己滚动，底部固定输入区；弹层打开/关闭与 URL/导航关系明确，点击关闭、Esc 和遮罩返回原阅读位置，焦点正确恢复。不把整个正文、已读位置或用户正在写的评论丢掉。

手机浏览器：操作按钮可缩成底部工具条/靠右紧凑 dock；评论使用屏内全高抽屉或适合触控的底部面板，可滑动关闭但不影响评论列表内部滚动，避免软键盘遮住输入。点击文章正文图片继续使用已有 Lightbox、标题/作者/地点链接保持可访问。长文章不强制以“像短视频一样每屏翻页”的交互呈现；用户的短视频截图只作互动控件和评论面板参考。

现有 `GuideActions.vue` 真实点赞/收藏/未登录跳登录/401 处理和 `GuideComments.vue` 真实评论、删除、分页、草稿保护全部保留；将原有逻辑抽取为可复用 composables / 可控组件再重新排布，禁止复制请求状态和重复 POST。点赞、收藏数字必须以实际后端为准，用户参考截图中的“2万/398”只是版式示例，不得写入真实数据。

评论“回复线程 / 评论点赞 / 最热/最新”属于 P1：只有在后端 API、权限、删除/审核/防滥用、数据库迁移可控时才能实现并显示按钮；在这之前不要显示假的回复按钮或假点赞数。P0 可以先完成平铺评论的高质量侧栏，并在结构上为线程预留空间。

## 6. P0：全站动效和交互质感

参考 08 图，建立一组复用语义动效 token：
- 动效时长（建议）：常规按下/图标 120—180ms、悬停 150—220ms、卡片进入 180—260ms、评论抽屉 220—280ms、弹窗/图片灯箱 180—280ms；真实应用由 DSH 根据效果微调，避免所有元素同时飞入。
- Header：当前 Tab/主题切换、头像弹层有轻微过渡；搜索聚焦边框和提示，导航展开与关闭准确；浮层仍可键盘操作。
- Feed：卡片渐入、图片加载骨架/淡出、缩略图 hover 轻放大、卡片略上移，滚动追加卡片只对新增项动画，不对旧卡片重新触发。
- 互动：点赞/收藏状态切换时心形或书签轻弹、计数轻过渡；失败回滚有清晰反馈，不要先动画“成功”后忽略失败。
- 详情：作者/标签交互 hover/focus、评论侧栏 slide + fade、点击图片放大/缩回原位、返回阅读位置保留。
- 个人主页：头图、头像、选项卡切换与卡片进入的统一节奏；设置对话框轻盈，不必用大型页面切换。
- 全局：仅在有信息价值时出现 Toast/Skeleton/错误反馈；优先 transform/opacity，避免动画 `width/height/top/left` 导致布局抖动；尊重 `prefers-reduced-motion` 和低性能环境，全局不使用高强度泛光/粒子/大面积背景漂移。
- 要求真实截图 + 小段浏览器录屏或 Playwright 时间点截图用于验收动效。不能拿静态参考图冒充动效已实现。
