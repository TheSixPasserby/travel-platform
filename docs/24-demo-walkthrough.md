# 毕业设计演示流程

演示使用已验证的数据库副本和授权图片。先按 [本地开发](14-local-development.md) 启动当前版本，确认迁移已完成，再准备作者、普通用户和管理员账号。密码由操作者本地保存。

## 约十分钟的主流程

| 时间 | 操作 | 可观察结果 |
|---|---|---|
| 0–1 分钟 | 首页浏览、切换城市或主题，执行跨类型搜索 | 真实公开结果、稳定加载和可访问入口 |
| 1–3 分钟 | 作者打开草稿，修改图文、选择景点并发布 | 编辑内容进入公开详情，首次发布时间语义保留 |
| 3–5 分钟 | 普通用户点赞、收藏、发表评论，作者回复并提及该用户 | 真实互动、两级线程和账号选择 |
| 5–6 分钟 | 收件人打开通知并点击对应事件 | 未读变已读，定位到实际回复 |
| 6–8 分钟 | 在攻略选择景点，创建或追加私人行程，调整项目顺序并刷新 | 地点来自源关系，保存及顺序持久化 |
| 8–9 分钟 | 打开 AI 工作台，演示预览或服务关闭时手动入口 | 生成与保存分开，失败仍可手动规划 |
| 9–10 分钟 | 管理员隐藏评论再恢复，切换手机宽度和主题 | 治理生效、历史关系保留、页面可操作 |

## 权限和异常补充

- 访客执行写操作时进入登录流程。
- 用户 A 打开用户 B 的私人行程时，后端拒绝访问。
- 重复点赞或收藏保持单条关系。
- 重新确认相同导入请求返回既有回执。
- 公开内容隐藏后，评论、通知及分享按相应可见性规则处理。

## AI 演示的范围

使用真实供应商时先确认可用配置和费用。采用本地 HTTP 合成供应商时，在截图和说明中保留其标识，仅演示预览、编辑与持久化链路。服务关闭时直接展示手动规划。

## 结束检查

确认作品状态、通知已读、行程与后台操作结果。演示副本内的数据由操作者决定保留或清理，原业务数据保持其用途。实际执行的测试和浏览器证据见 [M17 报告](../output/m17/项目P1完成情况与真实测试报告.md)。
