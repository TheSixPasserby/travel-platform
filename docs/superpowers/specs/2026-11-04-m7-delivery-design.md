# M7 系统交付与毕业演示设计

## 意图与范围

用户要求持续完成可运行、可演示、可解释的毕业设计，并保留规划与审查。M0–M6已验收，P0/P1功能齐备；本阶段完成交付链路，不增加业务子系统。学校日期/格式、域名/主机尚未知，先交付可搬运软件和Markdown材料，外部正式上线、学校最终验收明确不宣称完成。沿用Codex主导、DSH Flash Max执行，不自动commit。

## 方案选择

1. 仅开发服务器说明：最少工作，但没有验证可执行JAR与生产前端，不足以交付。
2. **采用JAR + Vite生产dist + Nginx示例**：保留Java21/MySQL8.x模块化单体，无新运行库。本机通过JAR与Vite preview代理演练生产构建；preview仅为本机演练，不作为公网生产服务器。实际Nginx/HTTPS部署等待目标环境。
3. Docker Compose：可移植但本机Docker服务未运行，引入额外维护与无法实测部分，本阶段不采用；不影响已有3306/3307服务。

## 交付结构与运行

- `scripts/backend.py jar`：安全复用现有.env解析与Java21选择，运行backend/target中唯一的.jar，缺失/多份拒绝且不运行Maven。不会建库或改全局配置。上传仍在项目根uploads，保证持久化。
- Vite服务端环境`TRAVEL_API_TARGET`默认`http://127.0.0.1:8080`，仅供开发/preview代理，绝不使用VITE_承载秘密。现安装Vite源码preview.proxy默认继承server.proxy，真实演练确认。
- 演练显式`SERVER_ADDRESS=127.0.0.1 SERVER_PORT=8081`与preview5174→8081，保留8080开发后端和5173前端；项目数据库仅3307独立8.4，原3306不参与。端口占用即失败，只停止记录且核实归属的自有PID。验证公开读取、受保护401、页面深链刷新、登录写读与上传路径，只操作新自有夹具，记录精确ID并清理，不触碰未知数据。
- `scripts/release.py OUTPUT`：先完整backend package和frontend build，通过后在不存在的OUTPUT创建交付目录。显式白名单复制源码/锁文件/Maven Wrapper/数据库/文档/启动脚本/.env.example/可执行JAR与dist，生成SHA256SUMS；assemble复用select_jar，缺包/多包/必需输入缺失不创建输出。拒绝符号链接，不复制.env/.local/.git/.superpowers/node_modules/真实上传/日志/.DS_Store或application-local/prod配置；uploads只有说明或占位。docs/superpowers设计计划有意交付，区别于隐藏执行日志。识别application*.yml/properties密码/API密钥字段，拒绝非空字面值、允许环境占位，不声称发现任意秘密。不自动安装依赖或发布外部服务。
- `deploy/nginx.conf.example`提供同源/API与uploads反代、SPA深链和静态缓存示例；路径/监听/HTTPS由部署者按目标配置，未执行nginx检查须标记。

## 演示数据与材料

先提供完整可复制的演示脚本/示例正文，涵盖游客、作者、另一用户、管理员与私人行程；优先通过API/UI创建、密码随机且仅保存忽略的本地600文件。持久演示账号与验收临时夹具区分，所有ID记录；不提供固定明文默认密码、不新增角色变更API。管理员通过人工数据库操作，以随机用户名+注册响应ID+本地凭据确认归属，SELECT核对角色/状态/未删后精确UPDATE；系统无邮箱字段。可重复执行时读取检查点续建，不覆盖同名未知账号，不自动删除用户数据。换机按无秘密步骤重建演示，不复制本机凭据或检查点，不承诺自动迁移演示数据。

文档包括部署/环境变量/初始化边界、备份与恢复流程、用户与管理员手册、10分钟演示顺序、需求→实现→测试追踪矩阵、论文大纲和答辩提纲。所有结论源于已有证据，TC-020标明AI未接入/核心无依赖，不伪造AI故障测试；性能/公网TLS/灾备恢复未实测则如实保留。论文不编造学校要求、实验结果或文献。
