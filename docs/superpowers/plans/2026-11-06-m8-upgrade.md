# M8 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 项目实际执行使用已核实的DSH Crew代理；共享契约和最终集成归Codex。用户要求覆盖技能默认流程：不自动commit/push，先完成Phase0汇报。

**Goal:** 安全完善原三篇攻略、六城及24–36景点，交付真实平台数据驱动的AI预览、编辑、单日重生成和确认保存。

**Architecture:** 扩展destinations及图库/攻略关系，保留主目的地与现有行程三表。AI只做受限检索与结构化预览，最终保存经通用整程导入事务。每阶段独立验收，不一次性堆叠系统。

**Tech Stack:** Java21、Spring Boot3.5.16、MyBatis-Plus3.5.18、MySQL8.4.13、Vue3.5.44、TypeScript5.9.3、Vite7.3.7，现有Sa-Token与受管上传。

**Spec:** [技术方案](../specs/2026-11-06-m8-upgrade-design.md)、[正式输入](../../m8/00-implementation-spec.md)、[审计基线](../../28-m8-phase0-audit.md)。

## Global Constraints

- 禁止清空数据库、重建数据库、TRUNCATE、批量覆盖未知记录或删除后重灌。
- 不得删除原有用户、攻略、评论、点赞、收藏、行程及关联。
- 草稿只完善内容，不得擅自发布。
- 所有数据库写入由主代理接管；DSH不得自行执行数据库写入、部署、提交或推送。
- .env/.local/Key/上传/原始备份不进入Git；来源清单不得包含私人凭据。
- 先备份、在新独立空副本验证恢复/升级后，才对已确认的本机开发库做增量写入；生产库、破坏性操作、外部发布或真实API费用须先征得同意。
- 两种运行模型分别核实；DSH固定buddy/deepseek-v4.1-flash/max，不自动升档。
- 同一cwd写任务串行。只有已证明独立检出且无共享写入时才并行；只读任务可以allow_concurrent_cwd。
- DSH遇权限/凭据围栏必须停止该文件并报告，不得换工具绕过；主代理在自身授权内接管。
- 每项先写有意义的失败测试→实际运行确认失败→最小实现→实际复验→diff/来源审查→更新PROJECT_STATUS。文档/素材排版不写镜像测试。

## Review Focus

1. 内容预览后原记录被用户修改：事务锁内指纹/updated_at变化即停止该篇，不能覆盖；Task1和Task5分别覆盖首次内容与后续关联的漂移测试。
2. 原客户端省略新增scenicSpotIds：保持原关系；显式[]才清空；Task4覆盖旧客户端兼容。
3. 模型等待时城市/景点停用：预览返回前与最终保存再次校验；Task7/8覆盖，不长时间持有锁。
4. 单日生成过程中另一天被编辑或需求变化：迟到响应不能覆盖；Task9覆盖需求版本和日编辑版本。
5. 保存请求超时后重发：同用户clientRequestId只有一份行程，失败无半成品；Task8覆盖唯一键并发及事务回滚。
