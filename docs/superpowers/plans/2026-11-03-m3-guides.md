# M3 攻略核心 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 作者能安全地完成草稿、发布、编辑与删除，游客能搜索和阅读攻略。

**Architecture:** 复用模块化单体及现有 MySQL 表。Codex 维护共享契约、配置和整合；DSH Flash/Max 执行边界明确的小任务。所有写操作使用数据库事务、当前行锁和后端作者校验。

**Tech Stack:** 现有 Java21/Spring Boot3.5/MyBatis-Plus/Sa-Token；Vue3/TypeScript/Pinia/Vitest；已核实markdown-it15.0.3与DOMPurify3.4.17（均自带类型）。

**Spec:** [M3 设计](../specs/2026-11-03-m3-guides-design.md)。共享约束见 [API](../../06-api-contract.md) 第 11、13–15 节。

## Global Constraints

- 前置门槛：M2 浏览器验收、前端独立审查、最终状态闭环后才实现 M3 生产代码。
- 无 DDL、无自动 commit、无全局模型切换；Codex 保留 GPT-6.1-Sol / Ultra，DSH buddy / deepseek-v4.1-flash / max。
- ID 字符串；HTTP 状态和业务码沿用 API；所有写接口实时认证和所有权校验。
- title180、content100000、summary500、season40 码点；images≤20、tags≤10、travelDays1–365；预算 DECIMAL(10,2) 字符串。
- 工作区无初始 commit，不为 worktree 创建提交；继续使用文件快照、限定所有权和 diff 审查。

## Review Focus

- HIDDEN 通过普通 PUT 或重复发布绕过治理：Task2 的真实 HTTP 状态矩阵。
- 关系写入后校验失败造成半套数据：Task2 的事务回滚断言。
- 撤回后再发布改变排序时间：Task2 的首次 publishedAt 保持断言。
- Markdown 经过解析仍有危险协议或外链图片：Task3 的 DOM 与浏览器攻击载荷。
- 迟到响应覆盖编辑页、401 卸载上传子组件后留空页：Task4 的异步回归和真实浏览器。
