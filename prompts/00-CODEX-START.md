# Codex 项目启动总提示词

你现在接手一个新的毕业设计项目，请担任项目主代理（Lead Engineer），在当前目录开始实施。

项目：旅游攻略分享与行程规划平台。

## 最高优先级约束
1. 先完整读取 `AGENTS.md`、`README.md`、`PROJECT_STATUS.md`。
2. 按需读取 `docs/`、`database/`。
3. 采用双模型协作，两类模型不同是有意设计：你（Codex 主代理）保留 **GPT-6.1-Sol / Ultra**，负责总体规划、架构决策、任务拆分、代码整合、质量控制和最终验收；DSH Subagent 使用 **CodeBuddy DeepSeek V4.1 Flash / Max**，承担编码、测试、文档整理和专项审查。启动时分别核对两侧所属模型，无需相同；模型必须在运行时核实，项目文件不能代替运行时设置；不修改 Codex 全局模型配置，不擅自切换模型。
4. 你负责最终架构决策、代码整合、测试和进度维护。
5. 可以使用 DSH 作为 Subagent，但先检查当前会话真实可用的 DSH 能力和调用方式。禁止臆造命令、工具名或参数。
6. 同一时间不得让多个代理无协调地修改同一文件。
7. 按里程碑交付可运行增量，不一次性生成全部系统。
8. 不擅自引入微服务、Redis、消息队列、Elasticsearch、向量数据库、RAG、Kubernetes 或复杂地图。
9. 不伪造构建、测试、子代理执行或模型配置结果。
10. 不覆盖未知文件，不执行破坏性数据库操作，不擅自提交 Git commit。

## 技术基线
Vue 3 + TypeScript + Vite、Tailwind CSS、Vue Router、Pinia、Axios；Java 21 + Spring Boot 3.x + Maven、MyBatis-Plus、Sa-Token、MySQL 8.x；模块化单体；REST `/api/v1`；本地图片存储；AI 为可选后端外部 API。

## 优先级
P0：注册登录、个人资料、攻略发布/浏览/编辑/删除、点赞收藏评论、目的地管理、搜索分页、图片上传、资源所有权校验。
P1：个人中心、我的攻略/收藏、手动行程规划、每日安排和排序、基础后台、响应式布局。
P2：AI 推荐、统计、地图。P0/P1 稳定前不大量投入 P2。

## 第一轮：基线审查
1. 检查工作区、Git 状态和环境版本；不得覆盖用户已有代码。
2. 分别检查 DSH 能力，以及 Codex 与 DSH 各自所属模型是否符合双模型分工。
3. 若 DSH 可用且能核实其指定模型配置，可并行最多 3 个只读审查：
   - 需求与验收；
   - 数据库 ER/DDL/索引；
   - 架构/API/前端页面。
4. 检查需求、架构、页面、流程、数据库、API 和 SQL 一致性。
5. 重点核对表名字段、权限、攻略状态、目的地状态、行程日期、AI 输出保存规则。
6. 先修复文档和 SQL 初稿，再进入实现。

若无法核实 DSH 子代理的指定模型配置，不要派发该子代理；Codex 侧与 DSH 侧模型本来就不需要相同，这不是派发阻塞条件。

## 第二轮：工程骨架
创建 Spring Boot 3.x 后端和 Vue 3 前端，配置 MySQL、MyBatis-Plus、Sa-Token、BCrypt、统一响应、异常处理、参数校验、SpringDoc、开发/生产配置；前端配置 Router、Pinia、Axios、Tailwind、基础布局。依赖选兼容稳定版本并记录。

## 第三轮：注册登录垂直切片
实现 users 表、注册、登录、退出、当前用户、BCrypt、Sa-Token、后端拦截、前端页面和路由守卫、测试。

验收：
- 新账号可注册；
- 重复账号被拒绝；
- 正确密码可登录，错误密码失败；
- 退出后受保护接口不可访问；
- 响应不泄露密码哈希；
- 后端权限不依赖前端按钮隐藏。

## UI 要求
现代旅游平台风格：暖白/米白、自然绿或蓝绿色、旅游摄影、留白、清晰排版、攻略卡片、目的地详情、行程时间线；桌面端优先并适配手机。用户端不要做成 Element Plus 后台模板。

## 交付要求
每个里程碑执行构建和测试、检查 diff、更新 `PROJECT_STATUS.md` 和受影响文档，列出修改文件、实际测试命令/结果、未解决问题和下一步。

## 现在开始
先做第一轮基线审查，不要直接大规模写代码。完成后汇总阻塞问题、模型/DSH 状态和修订内容；无阻塞时继续创建工程骨架并完成注册登录垂直切片。只在必须由用户决定时提出最关键的问题，其余按已确认基线合理处理并记录。
